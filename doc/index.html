Construisez l’interface d’édition qui correspond à vos composants.

Visual Page Editor fournit un Web Component, une bibliothèque de fields et un aperçu serveur. Vous déclarez vos blocks ; l’éditeur produit une structure JSON prête à être rendue par votre application.

01 — Installation

Installer la librairie

Le package publie un module ES et une feuille de style. Node.js et npm sont nécessaires pour l’installation. 

npm install visual-page-editor

Pour travailler directement depuis le dépôt :

npm install
npm run dev        # interface Vite sur http://localhost:5173
npm run server     # aperçu Edge/Fastify sur http://localhost:8000
Styles requis. Importez visual-page-editor/style.css une seule fois dans votre point d’entrée.

02 — Mise en place

Initialiser l’éditeur

  1. Importez la classe, les fields et la feuille de style.
  2. Enregistrez vos blocks avec registerBlock.
  3. Déclarez le Custom Element avec defineElement.
  4. Insérez l’élément dans une page, idéalement dans un formulaire. 
import {
    Text,
    VisualEditor,
} from "visual-page-editor";
import "visual-page-editor/style.css";

const editor = new VisualEditor();

editor.registerBlock({
    name: "heading",
    label: "Titre",
    category: "Contenu",
    usableInSlot: true,
    fields: [
        Text("title", {
            label: "Texte",
            defaultValue: "Bonjour !",
        }),
    ],
});

editor.defineElement("visual-editor");
<form method="post">
    <visual-editor
        name="content"
        shown="true"
        value="[]"
        urlPreview="/preview"
        iconsUrl="/icons/{{name}}.svg">
    </visual-editor>
</form>
Attributs du Web Component
Attribut Rôle Valeur par défaut
name Nom du <textarea hidden> généré pour la soumission du JSON. content
value Tableau JSON initial des blocks. Doit être un JSON valide. []
shown L’éditeur est visible uniquement quand la valeur vaut exactement "true". masqué
urlPreview URL appelée en POST pour rendre un block ou la page complète. chaîne vide dans l’élément connecté
iconsUrl Patron d’URL des icônes de blocks ; {{name}} est remplacé par leur nom. ./icons

Le bouton « Enregistrer » est un bouton de soumission. Placez donc l’éditeur dans un <form> pour recevoir le JSON dans le champ caché.

03 — Aperçu

Implémenter l’endpoint de rendu

L’éditeur envoie du JSON avec Content-Type: application/json. Une requête de block contient un objet ; une requête de page contient le tableau complet. La réponse attendue est du HTML. 

// Exemple de contrat, indépendant du framework serveur
app.post("/preview", async (request, response) => {
    const payload = request.body;

    const html = Array.isArray(payload)
        ? await renderPage(payload)
        : await renderComponent(payload._name, payload.data);

    response.type("text/html").send(html);
});
Sécurité. Le field HTMLText produit du HTML. Assainissez-le côté serveur selon votre politique avant de l’afficher sur un site public.

04 — Blocks

Déclarer un composant éditable

Options de registerBlock
Option Type Description
name string Identifiant technique écrit dans _name et envoyé au renderer.
label string Nom affiché dans la bibliothèque.
fields FieldDefinition[] Liste des fields et groupes éditables.
category string? Catégorie de classement dans la bibliothèque.
usableInSlot boolean? Autorise le block dans un Slot. Défaut : false.

05 — Configuration

Options communes aux fields

defineField ajoute automatiquement enabled: true et fusionne les valeurs par défaut. Toutes les options peuvent aussi être une promesse, une fonction dérivée des données du block ou une référence créée avec ref.

Option Type Comportement
label string Libellé visible. Requis par la majorité des fields, parfois fourni par défaut à "".
description string? Aide affichée sous le libellé lorsque le field utilise le wrapper Field.
defaultValue dépend du field Valeur injectée à la création d’un block.
enabled boolean | (data) => boolean Désactive visuellement et fonctionnellement le field si faux. 
Text("buttonLabel", {
    label: "Libellé",
    enabled: (data) => data.showButton,
});

Repeater("items", {
    label: "Éléments",
    max: ref<number>("limit"),
    fields: [Text("title", { label: "Titre" })],
});

Select("remoteItem", {
    label: "Élément distant",
    options: fetchOptions(), // Promise acceptée
});

07 — Extension

Créer un field avec defineField

Un renderer reçoit value, onChange et les options fusionnées. defineField transforme ce renderer en factory typée (name, options). 

import { defineField, Field } from "visual-page-editor";

type RatingOptions = {
    label: string;
    description?: string;
    defaultValue?: number;
    max?: number;
};

const defaults = {
    defaultValue: 0,
    max: 5,
};

const RatingRenderer = ({ value, onChange, options }: {
    value: number;
    onChange: (value: number) => void;
    options: RatingOptions & typeof defaults;
}) => (
    <Field label={options.label} description={options.description}>
        <input
            type="range"
            min="0"
            max={options.max}
            value={value}
            onChange={(event) => onChange(Number(event.target.value))}
        />
    </Field>
);

export const Rating = defineField<
    RatingOptions,
    number,
    typeof defaults
>({
    defaultOptions: defaults,
    render: RatingRenderer,
});

// Utilisation
Rating("score", { label: "Note", max: 10 });
Valeur initiale. Mettez systématiquement une valeur exploitable dans defaultOptions.defaultValue. Pour un field contenant fields, la factory construit l’objet initial à partir des valeurs par défaut enfants.

08 — Internationalisation

Ajouter une traduction

La traduction française complète est exportée sous le nom FR. Créez un objet complet en partant de cette base, surchargez les libellés voulus et passez-le au constructeur. Les clés propres à votre projet sont autorisées et deviennent accessibles via translation(key). 

import {
    FR,
    VisualEditor,
    translation,
} from "visual-page-editor";

const en = {
    ...FR, // garantit que toutes les clés internes existent
    save: "Save",
    addComponent: "Add component",
    closeEditor: "Close editor",
    heroCategory: "Hero",
};

const editor = new VisualEditor({ lang: en });

editor.registerBlock({
    name: "hero",
    label: "Hero",
    category: translation("heroCategory"),
    fields: [],
});

Le constructeur accepte aussi devices. Chaque appareil a un name, un type (desktop, tablet ou mobile), une taille [largeur, hauteur], une orientation facultative et éventuellement default: true.

09 — Données

Structure produite

[
    {
        "_name": "heading",
        "_id": "identifiant-uuid",
        "data": {
            "title": "Bonjour !"
        },
        "config": {
            "id": "",
            "class": "",
            "css": ""
        }
    }
]

_name sélectionne le renderer, _id stabilise l’édition et data contient les valeurs des fields. config est facultatif et porte l’identifiant HTML, les classes et le CSS personnalisé du block.
